package envelope // import "github.com/agent-fox-dev/aflib/envelope"

Package envelope defines the JSON object the agent-fox commands write to stdout,
as Go types a program can decode it into, and the result of the issue command
(cmd/issue) that this module ships.

A command writes exactly one JSON object on every program-driven path, including
the failing ones: an Envelope. Its result property holds the command's own
result, whose type depends on the command:

    issue  an IssueResult  a thread, a repository, a list of issues, or what a write did

Decode a command's output with the function for its result:

    env, err := envelope.DecodeIssue(stdout)
    if err != nil {
    	return err // not an envelope at all
    }
    if !env.OK {
    	return env.Error // an *ErrorInfo: stage, category, message, fix hint
    }
    fmt.Println(env.Result.Issue.Title)

Decode is the same for any other result type, and Envelope[any] reads a result
of a shape the caller does not know.

The JSON is that of the envelope the spec repository's commands (spec, specr,
speca) write, without the properties only a model-driven command writes
(artifacts, input, model, usage). A decoder of either reads the other: the
properties one does not know are ignored.

The package imports the standard library and issuex, whose value types
IssueResult reuses.

# Compatibility

The types follow the commands' output. Fields are added over time and a decoder
ignores the ones it does not know; a field's name and meaning do not change.
Code, category and stage names are open sets: a value this package has no
constant for is not an error.

CONSTANTS

const (
	// ExitOK means the command did what it was asked.
	ExitOK = 0
	// ExitFailed means a step errored. The failing stage is named in the
	// envelope's error object.
	ExitFailed = 1
	// ExitUsage means the invocation was wrong: an undefined flag, a flag
	// combination that cannot hold, an input that names nothing. Nothing was
	// written.
	ExitUsage = 2
)
    Exit codes. Something other than a human reads them.

const (
	// SeverityHigh means the result is not quite what it appears to be.
	SeverityHigh = "high"
	// SeverityLow means the warning is informational.
	SeverityLow = "low"
)
    Warning severities.

const (
	// CategoryUsage is an invocation that was wrong. Nothing was written.
	CategoryUsage = "usage"
	// CategoryAuth is a missing or rejected credential. Re-running changes
	// nothing until the environment does.
	CategoryAuth = "auth"
	// CategoryInput is an input that could not be read or does not exist: an
	// issue the forge does not have, a request it refused as invalid, or a
	// forge that cannot be told.
	CategoryInput = "input"
	// CategoryConflict is a write the state of the forge does not allow, such
	// as a pull request that cannot be merged.
	CategoryConflict = "conflict"
	// CategoryAPI is a provider or transport failure, a rate limit included.
	// It is retryable.
	CategoryAPI = "api"
	// CategoryAborted is a call that was cancelled or outlived its timeout.
	// It is retryable.
	CategoryAborted = "aborted"
	// CategoryInternal is a bug in the command.
	CategoryInternal = "internal"
)
    Error categories: the kind of failure, which says whether re-running could
    help. The set is open; a category with no constant here is still valid.


FUNCTIONS

func Encode(v any) ([]byte, error)
    Encode renders v as indented JSON and a trailing newline, the way a command
    writes its envelope. It does not escape <, > and & as encoding/json does by
    default: the output is read by programs and models, never embedded in HTML,
    and Markdown in a body is full of them.

func RetryableFor(category string) bool
    RetryableFor reports whether an error of the given category can succeed if
    re-run unchanged. Only "api" and "aborted" are retryable.

func StatusFor(code int) string
    StatusFor maps an exit code to its status string: done, usage or failed.


TYPES

type Envelope[R any] struct {
	Tool     string `json:"tool" description:"the command that wrote this envelope"`
	Version  string `json:"version" description:"the command's build identity"`
	OK       bool   `json:"ok" description:"true only when the command did the whole job it was asked to do; never true beside a non-zero exit_code or an error"`
	Status   string `json:"status" description:"the outcome in words, derived from exit_code: done (0), failed (1) or usage (2)"`
	ExitCode int    `json:"exit_code" description:"the process exit code: 0 done, 1 failed, 2 usage error"`
	Summary  string `json:"summary" description:"one sentence on the outcome, at most 200 characters"`

	Error       *ErrorInfo   `json:"error,omitempty" description:"what failed and where; present exactly when ok is false"`
	Warnings    []Warning    `json:"warnings,omitempty" description:"what went differently than intended without stopping the call"`
	Result      R            `json:"result,omitzero" description:"the command's own result"`
	SideEffects []SideEffect `json:"side_effects,omitempty" description:"every write to a forge, in the order it was made, a failed one included"`
	Next        []Next       `json:"next,omitempty" description:"the invocations a caller would plausibly make next"`

	DurationMS int64  `json:"duration_ms" description:"wall-clock time of the call, in milliseconds"`
	StartedAt  string `json:"started_at" description:"when the call started, RFC 3339 in UTC"`
}
    Envelope is the single JSON object a command writes to stdout. R is the type
    of the command's own result, IssueResult for issue. Use a pointer type,
    as IssueEnvelope does, to tell an absent result from an empty one; a failure
    that happened before there was anything to report has none.

func Decode[R any](data []byte) (Envelope[R], error)
    Decode reads the envelope a command wrote. It fails when data is not one
    JSON object, or when a field has the wrong type; unknown fields are ignored.
    A command writes exactly one object, so data after it is an error too.

type ErrorInfo struct {
	// Stage is the step that failed: usage, forge (the forge or its client
	// could not be set up), read, write, or schema.
	Stage string `json:"stage" description:"the step that failed"`
	// Category says whether re-running could help.
	Category  string   `json:"category" description:"the kind of failure, which says whether re-running could help; an open set"`
	Message   string   `json:"message" description:"what failed, in words"`
	Retryable bool     `json:"retryable" description:"whether re-running the identical command could succeed"`
	Resumable bool     `json:"resumable" description:"whether re-running the same input continues the work rather than starting it over"`
	FixHint   *FixHint `json:"fix_hint,omitempty" description:"a mechanical remedy, where one is known"`
	// Has unexported fields.
}
    ErrorInfo says what failed and where. It is present exactly when ok is
    false. It is an error, so a caller can return it as it is.

func (e *ErrorInfo) Error() string

func (e *ErrorInfo) Unwrap() error
    Unwrap returns the failure the command raised this from. It is set only in
    the process that ran the command; an ErrorInfo decoded from JSON has none.

func (e *ErrorInfo) WithCause(err error) *ErrorInfo
    WithCause records the failure e reports, for Unwrap, and returns e.

type FixHint struct {
	Flag  string   `json:"flag,omitempty" description:"the flag to change"`
	Env   []string `json:"env,omitempty" description:"the environment variables, one of which supplies what is missing"`
	Valid []string `json:"valid,omitempty" description:"the values the flag accepts here"`
}
    FixHint is a machine-usable remedy for a failure.

type IssueEnvelope = Envelope[*IssueResult]
    IssueEnvelope is what the issue command writes.

func DecodeIssue(data []byte) (IssueEnvelope, error)
    DecodeIssue reads the envelope the issue command wrote, whichever of its
    forms it was. Which fields of the result are set tells the forms apart.

type IssueResult struct {
	Forge string `json:"forge" description:"the forge the call went to: github or gitlab"`
	Repo  string `json:"repo" description:"the repository, owner/name; a GitLab owner may hold subgroups"`
	Host  string `json:"host,omitempty" description:"the repository's web host, when the input or the origin remote named one"`
	Ref   string `json:"ref,omitempty" description:"the thread: owner/name#N for an issue, owner/name!N for a pull or merge request; runnable as the input of the next call"`

	// The read of a thread, and the thread after a write to it.
	Issue             *issuex.Issue        `json:"issue,omitempty" description:"the issue, or the issue view of a pull request: title, body, state, labels, author"`
	Comments          []issuex.Comment     `json:"comments,omitzero" description:"the thread's comments, oldest first; [] when it has none. Read forms only"`
	CommentsTruncated bool                 `json:"comments_truncated,omitempty" description:"the thread has more comments than were read (the client reads at most 500)"`
	PullRequest       *issuex.PullRequest  `json:"pull_request,omitempty" description:"the pull or merge request: branches, head commit, draft and merged"`
	Checks            []issuex.CheckRun    `json:"checks,omitzero" description:"with --checks, the CI checks of the head commit"`
	Reviews           []issuex.Review      `json:"reviews,omitzero" description:"with --reviews, the reviews of the pull request"`
	Files             []issuex.ChangedFile `json:"files,omitzero" description:"with --files, the files the pull request changes"`

	// The read of a repository.
	Repository *issuex.Repository `json:"repository,omitempty" description:"the repository: default branch, visibility, the caller's permissions and the merge methods allowed"`

	// --list.
	Issues     []issuex.Issue `json:"issues,omitzero" description:"with --list, the issues that match, without pull requests; [] when none does"`
	Incomplete bool           `json:"incomplete,omitempty" description:"with --list, more issues match than --limit allowed"`

	// The write forms.
	CommentURL string              `json:"comment_url,omitempty" description:"with --comment, the web URL of the comment"`
	Label      *issuex.Label       `json:"label,omitempty" description:"with --create-label, the label asked for; a label that already existed is not an error"`
	Merge      *issuex.MergeResult `json:"merge,omitempty" description:"with --merge, the forge's answer: merged, the merge commit and its message"`
	NoChange   bool                `json:"no_change,omitempty" description:"the thread was already in the state asked for (--close on a closed one, --reopen on an open one); nothing was written"`
	DryRun     bool                `json:"dry_run,omitempty" description:"the call ran under --dry-run: nothing was written, and planned lists what would have been"`
	Planned    []PlannedWrite      `json:"planned,omitzero" description:"under --dry-run, the writes the call would have made, in order"`
}
    IssueResult is the result of the issue command. Every form sets Forge and
    Repo, and Ref when it names a thread; the other fields are those of the
    form, and the ones a form does not produce are absent.

type Next struct {
	Tool  string   `json:"tool" description:"the command to run"`
	Input string   `json:"input" description:"its one positional input; empty when the call takes none"`
	Flags []string `json:"flags" description:"the flags to add, each value its own element"`
	Why   string   `json:"why" description:"why a caller would run it"`
}
    Next is one suggested follow-up invocation: the tool, its single input,
    the flags to add, and why.

type PlannedWrite struct {
	Action string `json:"action" description:"what would be written, as SideEffect.Action"`
	Kind   string `json:"kind,omitempty" description:"what it would be written to: issue, pull_request or repository"`
	Target string `json:"target" description:"the thread or the repository it would be written to"`
	Detail string `json:"detail,omitempty" description:"what it would carry, in words: the fields, labels or method"`
}
    PlannedWrite is one write a call under --dry-run would have made, named as a
    SideEffect of the real call would name it.

type SideEffect struct {
	Action  string   `json:"action" description:"what was written: create_issue, comment, edit, add_labels, remove_label, close, reopen, create_label, create_pull_request, review or merge"`
	Kind    string   `json:"kind,omitempty" description:"what it was written to: issue, pull_request or repository"`
	Target  string   `json:"target" description:"the thread (owner/repo#N, owner/repo!N) or the repository (owner/repo) written to"`
	URL     string   `json:"url,omitempty" description:"the web URL of what the write made, when the forge returned one"`
	OK      bool     `json:"ok" description:"whether the forge accepted the write"`
	Warning WarnCode `json:"warning,omitempty" description:"the warning raised about this write, if any"`
}
    SideEffect is one write a command made to a forge, in the order it was made.
    A write the forge refused is listed too, with OK false.

type WarnCode string
    WarnCode identifies one warning cause. It is an open set: a decoder must
    accept a code it has no constant for.

const (
	// WarnCommentsUnreadable: the thread was read and its comments were not.
	WarnCommentsUnreadable WarnCode = "comments_unreadable"
	// WarnCommentsTruncated: the thread has more comments than were read.
	WarnCommentsTruncated WarnCode = "comments_truncated"
	// WarnAssigneesIgnored: the forge's client does not send assignees, so
	// the ones asked for were not set.
	WarnAssigneesIgnored WarnCode = "assignees_ignored"
)
    The warning codes the issue command raises.

type Warning struct {
	Code     WarnCode `json:"code" description:"a stable code naming the cause; an open set"`
	Severity string   `json:"severity" description:"high when the result is not quite what it appears to be, low when informational"`
	Stage    string   `json:"stage" description:"the step that raised it"`
	Message  string   `json:"message" description:"what happened, in words"`
}
    Warning is one thing that went differently than intended but did not stop
    the call. Code is stable; Stage is the step that raised it.
